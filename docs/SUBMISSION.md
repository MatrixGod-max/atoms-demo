# 提交说明 — Fusion 聚变(对标 atoms.dev)

> ROOT / AI Native 全栈工程师笔试作品。一句话描述想法 → 智能体团队协作生成可运行、
> 可迭代、可验收、可发布、可被再创造的网页/移动应用。本文档回答三个问题:怎么做的、
> 做到了哪,以及继续投入会往哪走。功能细节见 [README](../README.md),
> 版本演进见 [CHANGELOG](../CHANGELOG.md)(v1–v17,均含当日时间戳)。

## 一、实现思路与关键取舍

**主线**:围绕"生成物的完整生命周期"搭一条真实可用的产品闭环 ——
想法 → 多智能体流水线(过程全程可见)→ 多文件工程 → 构建产物 → 版本/制品 →
独立域发布 → 被发现 / Remix / 聚变 → 反馈回流迭代。每个环节宁可范围小,也要是
真实现而非视觉占位;少数确属占位的(竞赛模式)在 UI 上如实标注"即将推出"。

关键取舍(为什么这样做):

| 决策 | 取舍理由 |
|---|---|
| **产物 = 文件树 + 构建产物**(v1–v16 单文件 → v17 工程模式) | 早期用单文件 HTML 把预览/存储/发布退化为一个字符串的读写,复杂度预算留给流水线与验证链;v17 保留"自包含单 HTML"这一下游契约,但把它变成 **esbuild 构建产物**:多文件 React 源码(依赖白名单)→ 服务端打包 → 构建报错按文件/行号喂回 Engineer 回炉 —— 真实的 代码→构建→报错→修复 开发循环,而预览/制品/PWA/部署整条下游零改动 |
| **多智能体流水线,阶段单一职责** | Planner 控范围 / Engineer 流式编码 / Build 构建 / Reviewer 静态评审 / Validator 真机实测;团队模式再加 PM(需求单+验收标准)与 Architect(蓝图),深度研究加 Researcher。SSE 把每阶段与代码逐 token 推到前端 —— "智能体在工作"是看得见的,不是转圈动画 |
| **验证链宁真实不表演** | Validator 用 headless Chrome 真实运行产物捕获运行时错误;验收标准被编译成**声明式交互测试 DSL**(click/type/assert…)逐条真实执行 —— LLM 产出的是数据不是代码,执行权在平台侧;运行时/验收失败一律**源码级修复→重建→复验** |
| **目标模式 = 服务端自治循环 + 三重预算兜底** | 设目标后由评估智能体逐轮打分、以缺口驱动下一轮,循环在服务端链式调度(关页面不中断);自治必须有预算约束:轮数上限 + 每日配额 + 积分扣费,任一触顶即优雅停止 |
| **Next.js 单体 + node:sqlite,零 ORM 零外部服务** | 一个进程覆盖 UI/API/队列/静态服务,部署面最小;Node 24 内置 SQLite(WAL)+ scrypt,依赖极薄。队列在进程内是单机取舍,横向扩展路径已想清楚(扩展 P1-2) |
| **安全边界前置** | 用户生成代码是不可信输入:发布应用走独立源(cookie/origin 隔离)、预览沙箱收紧、链接抓取带 SSRF 防护(拒私网/元数据地址)、全线限流+配额 |
| **积分经济真实扣费** | 生成消耗真实 LLM 额度,必须有成本闸门:按模式计价(快1/混3/深5,研究/团队/聚变/工程模式加价)、失败退款、注册/横幅/兑换码发放、套餐档位 —— 同时也是对标 Atoms 的产品形态 |
| **连接器 = 免密钥白名单代理** | 生成应用不许直连外网;天气/汇率/二维码走平台代理(参数校验+缓存+限流+CORS),真数据、零密钥、风险面可枚举 |
| **模型分档按阶段混用** | 快速(非思考)/混合(思考规划+非思考编码)/深度(全思考),时间线标注每阶段模型;底层 DeepSeek V4 Flash 单模型经 `thinking` 参数切换(旧名 2026-07-24 弃用,已提前迁移并保留兼容映射),OpenAI 兼容接口换模型只改环境变量 |
| **AGENT_MOCK 确定性流水线** | 整条链路(含目标循环、验收、聚变、工程构建)在无 LLM 环境可确定性复现 —— 72 例测试与 CI、e2e 冒烟全部零成本跑通 |

**工程方式**:按笔试要求全程 vibe coding —— Claude Code 驱动规划/编码/测试/部署/文档,
人工只做方向决策;期间多会话并行开发,每个版本当日提交并部署到生产验证。

## 二、当前完成程度

**已完成**(按能力域归纳;v1–v17 全部部署在生产实测过):

- **账号**:用户名/邮箱双通道注册与登录(至少一项,大小写不敏感唯一,旧库平滑迁移)、
  用户菜单(设置/套餐/个人主页/外观三态/兑换码/退出)、演示账号全功能开放
  (自带积分,仅不可改密码 —— 防共享账号被锁)
- **生成与工程**:🏗 工程模式默认(多文件 React 源码 + 依赖白名单 + esbuild 服务端构建,
  Build 阶段可见、构建报错回炉,工作台文件树 tabs,📦 导出 zip 含 vite/Capacitor 配置;
  可切回 ⚡ 单文件)· 三档模型混用(V4 Flash 思考/非思考)· 团队模式(PM/Architect)·
  深度研究(含链接抓取)· 附件(文件+文件夹)· 中文语音输入 · 主题持久化 · 网页/移动双目标
- **自治与精准迭代**:🎯 目标模式(评估-迭代服务端循环,达标/轮上限/积分/手动四路终止)·
  指哪改哪(预览点选元素,外科手术式修改)
- **验证**:Reviewer 评审 → Build 构建门 → Validator 真机运行 → 验收 DSL 真实执行,
  全部失败路径回炉修复并复验(工程模式为源码级修复→重建)
- **产物与发布**:版本历史/回滚 · 制品 registry(不可变 #n、latest 指针、永久快照)·
  移动制品自动 PWA(可安装/离线/扫码)· 独立应用域 · 专属子域 · S3/Netlify 部署 · Docker 自部署
- **分发与生态**:展厅/发现 · Remix · 聚变(双应用合并新应用,继承工程形态)· 个人主页 ·
  运营面板(访客反馈+线上报错,一键吸收/自愈)
- **平台设施**:云 KV(访客共享)· 连接器 ×3 · 积分/兑换/套餐 · 健康检查/每日备份/CI/
  72 例测试 + mock 全链路冒烟

**未做 / 已知边界**(如实):

- 工程模式依赖白名单目前仅 react/react-dom(平台内置),暂不支持任意 npm 包与多路由工程;
  云端不打原生包(导出 zip 附 Capacitor 配置与打包指引)
- 无邮箱验证/找回密码(SES 仍在沙箱,发信通道未开)——用户名注册也因此不影响安全模型
- 队列在进程内,单机部署;横向扩展需外置队列与事件流
- KV 公共写(按应用隔离+限流+容量上限约束);图片附件仅作资源内嵌,不做视觉理解(DeepSeek 纯文本)
- 竞赛模式(Race Mode)是唯一的 UI 占位
- 测试注:1 条验收 DSL 测试(真实 Chrome 交互)在 2 核演示机高负载下偶发超时,单独运行稳定

## 三、继续投入:扩展方向与优先级

优先级判断标准:**先解产品天花板(产物形态),再解规模(基础设施),后做生态(网络效应)**——
天花板决定上限,规模决定可靠,生态决定增长;倒过来做会在错误的地基上堆功能。
(原 P0-1「多文件产物 + 依赖白名单」已在 v17 落地,后续项相应前移。)

**P0 — 继续抬高产物与生成上限**

1. **依赖生态开放**:白名单扩展到受控 npm 包集(图表/动画/状态库等,服务端锁版本预打包)、
   多页面/路由工程 —— v17 的文件协议与构建门直接承接,改动集中在白名单与打包配置
2. **Race Mode**:同一 prompt 并发多模型生成、并排预览择优 —— 模型注册表与作业体系已就位,
   缺的是并发调度与对比 UI(也是唯一未兑现的占位入口)

**P1 — 规模与可靠**

3. **横向扩展**:队列外置(Redis/DB 轮询)+ SSE 事件走 pub/sub,多实例共享;目标模式评估器
   升级多维评分(加截图视觉评估,补足纯代码评审对视觉目标的盲区)
4. **账号与安全完善**:SES 出沙箱后上邮箱验证/找回密码;KV 写鉴权(应用级 token);OAuth 三方登录

**P2 — 生态与增长**

5. **连接器生态**:GitHub/Notion/Google Drive 等 OAuth 连接器(现有白名单代理架构直接承接);
   模板市场开放投稿;团队协作空间(多人共建一个项目,消息/版本体系已是天然基础)
